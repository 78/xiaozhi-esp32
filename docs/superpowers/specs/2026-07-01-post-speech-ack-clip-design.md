# Post-speech acknowledgment clip (device-local filler) — Design

**Date:** 2026-07-01
**Status:** Approved (design), pending implementation plan
**Component:** `xiaozhi-esp32` firmware (`tuni-p4`) + offline prompt generator. **No `robo-worker` changes.**

## Problem / motivation

After a child finishes speaking, there is a ~1.5–2s gap before Tuni's real reply
plays (device `listen.stop` → server STT ~0.5s → LLM + TTS first chunk ~1–1.5s).
During that gap the toy is silent, so a young child (5–8) doesn't know it heard
them. We want a short spoken acknowledgment ("Got it!", "I hear you, buddy!")
that plays in the gap so the child feels heard, without waiting on the network.

## Goals

- Play a short spoken ack shortly after the child stops talking, covering the
  pre-reply gap.
- Feel immediate and local (no dependency on server round-trip to *start* the ack).
- Never talk over / duplicate the real reply.
- Do not regress the noise work: the ack must not be re-captured by the mic, and
  it must not fire on non-speech.

## Non-goals

- Eliminating the *rare* false ack when a noise burst passes the device RMS gate
  (the device cannot know the transcript was empty — accepted trade-off of the
  device-local approach).
- Any `robo-worker` / bridge change. Pure firmware + assets.
- New user/config surface. Reuses the boot-prompt embedded-asset mechanism.
- Vietnamese acks (explicitly English per product decision).

## Design

### 1. Trigger & timing

```
child speaks → VAD onset (RMS-gated) → stream → falling edge → listen.stop sent
                                                                    │
                                                    arm ACK_DELAY_MS (~1000ms) timer
                                                                    │
   ┌── server reply (tts start) arrives first ──► cancel timer, NO ack
   │
   └── timer fires AND (state == listening) AND (WS connected) AND (not error/aborted)
            └──► play a random OGG_ACK_* clip (mic gated, see §3)
```

- Armed **only** when a real speech turn ends — i.e. when the device sends
  `listen.stop`. In the shipped config (`CONFIG_VAD_GATED_UPSTREAM`) that is the
  EOS-marker path in `application.cc` ("EOS marker, sending listen.stop"). The
  RMS onset guard already keeps `listen.stop` out of low-energy noise.
- **Reply always wins (hard-cut).** The server `tts` `state:start` handler already
  calls `ResetDecoder()` (application.cc:626), clearing the playback queue the ack
  uses, then enters `kDeviceStateSpeaking`. So: `tts start` **before** the timer
  fires cancels the pending timer (no ack); `tts start` **while the ack plays**
  hard-cuts it via that existing flush and the reply plays. There is no
  "let it finish." Keep clips short (≤~800ms) so a mid-clip cut is rare/brief.
- **Fire conditions** (all required): still in `kDeviceStateListening` (no reply
  yet), WebSocket connected, and not in an error/aborted/reconnecting state.
- `ACK_DELAY_MS` is a tunable constant (default ~1000ms, measured from
  `listen.stop`). Note `listen.stop` already trails the child by the VAD noise
  hangover (~700ms), so the ack lands ~1.5–1.7s after the child actually stops —
  still ahead of the real reply. Tune on hardware.

### 2. The clips

- **3–5 short English clips** in Tuni's English voice, embedded as
  `Lang::Sounds::OGG_ACK_1..N`, selected at random per turn with **no immediate
  repeat** (track last index).
- Default lines (easily swapped): "Got it!", "I hear you, buddy!",
  "Okay, let me think!", "Mm-hmm, one sec!", "Ooh, nice one!".
- Generated by the existing offline pipeline (`scripts/tuni_prompts/gen_prompts.py`),
  extended with **distinct** args that decouple TTS language from asset locale:
  `--tts-language en-US` (Google TTS `language_code`, replacing the hard-coded
  `vi-VN` at gen_prompts.py:23), `--clone-key <clone_key_en.txt>` (Tuni English
  clone), and `--locale-dir main/assets/locales/vi-VN` (where OGGs are written /
  embedded from). Input from a new `prompts.en.json`. The device is
  `CONFIG_LANGUAGE_VI_VN`-pinned; the ack clips are English audio but live in the
  active locale's asset dir as embedded byte blobs addressed by `OGG_ACK_*`. Same
  Opus/loudnorm encoding + `lang_config` regen + CMake `DEPENDS` wiring as the boot
  prompts.
- Voice consistency: `clone_key_en` yields Tuni's English clone. Confirm it
  matches conversational English Tuni ("A young british woman" persona) after a
  first generation; re-roll wording/voice if off.

### 3. Echo handling (critical)

The ack plays while the device is still in `kDeviceStateListening` with the mic
open. Skipping only the protocol-level `SendAudio` is INSUFFICIENT: the AFE keeps
producing output, VAD falling edges still call `MarkEndOfUtterance()`
(audio_service.cc:130) which enqueues an EOS marker, and already-queued upstream
frames still drain (application.cc:253). Any of these re-captures the clip → a
phantom turn on the worker (which is not replying, so it treats it as new speech).

**Mechanism — reuse the exact primitive `kDeviceStateSpeaking` already uses**
(application.cc:1021):

1. Before `PlaySound(OGG_ACK_*)`: `audio_service_.EnableVoiceProcessing(false)` —
   stops the audio processor (no AFE output → no VAD callbacks, no EOS markers) and
   calls `BumpUpstreamGeneration()` (audio_service.cc:761), discarding any in-flight
   upstream PCM / EOS marker already queued.
2. Play the ack — the playback/decoder path is independent of the stopped capture
   path.
3. Re-enable capture **only after** the clip finishes playing **and** only if still
   in `kDeviceStateListening`: `EnableVoiceProcessing(true)`. Note this call itself
   runs `ResetDecoder()` (audio_service.cc:748), so it must not run mid-clip.

If a real reply arrives during the ack, its `tts.start` handler drives
`kDeviceStateSpeaking` → `EnableVoiceProcessing(false)` + `ResetDecoder()`; the
state machine then owns cleanup and the later re-enable on return to listening. The
ack-completion re-enable in step 3 must therefore no-op when the state has already
left listening.

Requirement: **no ack audio reaches STT upstream and no phantom turn is generated.**

### 4. Interaction with real reply & stall filler

- `tts start` before the timer fires → cancel the pending timer (no ack).
- `tts start` *while the ack is playing* → the existing `ResetDecoder()` in the
  tts.start handler hard-cuts the ack and the reply plays (§1). We do NOT
  special-case "let it finish"; clips are short so the cut is rare and brief.
- The server `LLM_STALL_FILLER` is itself a TTS reply (arrives as `tts start`), so
  it cancels/hard-cuts the device ack the same way — no double filler.

### 5. Code touch points

- **`main/application.cc`**: arm the `ACK_DELAY_MS` timer where `listen.stop` is
  sent (gated EOS path); on fire, check §1 conditions then run the §3 sequence
  (`EnableVoiceProcessing(false)` → `PlaySound(random OGG_ACK_*)` → on playback
  completion, if still in `kDeviceStateListening`, `EnableVoiceProcessing(true)`).
  Cancel the pending timer on `tts start`, a new VAD onset, and abort/error/disconnect.
- **`main/audio/audio_service.*`**: random-no-repeat `OGG_ACK_*` selection + a
  playback-complete signal so `application.cc` knows when to re-enable capture.
  Reuses existing `EnableVoiceProcessing` / `BumpUpstreamGeneration` / `PlaySound`.
- **Assets/generator**: `scripts/tuni_prompts/prompts.en.json`; extend
  `gen_prompts.py` with `--tts-language`, `--clone-key`, `--locale-dir` (decoupling
  TTS language from asset locale); generate OGGs into `main/assets/locales/vi-VN/`;
  add `OGG_ACK_1..N` to embedded sounds + `lang_config` regen (DEPENDS wiring).

## Edge cases

- **Disconnected / reconnecting when timer fires** → no ack (guard).
- **Noise leaks past RMS gate** → turn gets a false ack (rare, accepted).
- **Child speaks again during the 1s wait** → voice processing is still on, so a
  new VAD rising edge fires and **cancels the pending ack timer**. The second
  onset's audio streaming follows existing gated behavior (device stays in
  `kDeviceStateListening`; `listen_stop_sent_` is already true so no second
  `listen.stop` until the state resets) — this feature does not change that, it
  only cancels the ack. Once the ack has *started*, capture is suppressed (§3) so
  no new onset can occur mid-clip.
- **Abort/stop** mid-wait → cancel ack.
- **Ack asset missing / decode fail** → no-op, never blocks the reply.

## Tunables

- `ACK_DELAY_MS` (default ~1000ms).
- Clip count `N` (3–5) and wording.

## Acceptance criteria (hardware)

1. Normal turn: child speaks → ack plays ~1s later → real reply follows, no
   overlap, no double filler.
2. Fast reply (reply < ~1s): no ack.
3. Ack audio is NOT re-captured (no phantom turn on the bridge/worker during ack).
4. Disconnected: no ack.
5. Silence/quiet room: no ack (no `listen.stop`, so timer never arms).
6. Clips vary across consecutive turns (no immediate repeat).
