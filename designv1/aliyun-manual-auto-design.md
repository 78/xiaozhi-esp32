# 阿里云 Manual / Auto 模式设计约定

日期：2026-11-16
状态：讨论结论，作为后续实现依据；本文不代表固件已经实现或完成实机验收。

## 1. 背景与范围

原 `design` 目录记录了 Waveshare ESP32-S3 Touch LCD 3.5B 的音频调试过程。最新结论见 [历史设计依据摘要](historical-reference.md#音频结论)：当前硬件与声学条件下，AEC 在双讲场景仍会抑制近端语音，尤其容易丢失句首、轻声和短词，因此本板暂时不启用设备侧 AEC。

后续阿里云对接范围收敛为 **Manual 和 Auto 两种交互模式**，暂不支持依赖持续上行和声学插话的全双工 Realtime 交互。这里限制的是交互模式，不排除使用阿里云 Realtime 接口承载这两种模式。

保留当前值得延续的 NSNet2 降噪，以及上行连续性、长回复缓冲和播放取消相关修复。AEC 的停用结论限定于当前 3.5B 板型及其使用条件，不推广到所有板型。

## 2. Manual 模式

由用户操作明确控制一轮收音：开始操作后上传麦克风音频，结束操作后结束本轮输入并请求回复。具体采用按住说话还是点击开始/结束，沿用后续确定的交互入口。

录音和回复播放按轮次进行。若用户在回复播放期间主动开始新一轮收音，应先停止旧回复、清理待播数据，再进入收音，避免旧回复声音混入新一轮输入。

## 3. Auto 模式：半双工

Auto 使用自动语音检测完成轮次切换，明确采用半双工策略：**设备播放服务器回复期间，不上传麦克风音频。**

正常流程：

1. 进入监听阶段，上传经过降噪处理的麦克风音频，由云端 VAD 判断用户发言结束。
2. 进入服务器回复阶段时关闭本轮上行，回复播放期间持续保持关闭。
3. 等待服务器本轮音频接收结束，并且设备本地解码、播放队列及在途输出排空。
4. 确认本地播放完成后，丢弃播放期间积累的麦克风音频及旧上行包，再恢复实时上行，进入下一轮监听。

服务器音频发送结束不等于设备播放结束，不能仅凭云端结束事件恢复上传。实现时还需确认 codec/DMA 中的尾部音频已播放完成；如实机存在声学余响，再根据测量确定是否需要短暂的恢复等待时间。

暂停上传不要求必须关闭物理麦克风采集。采集是否继续由本地音频处理需要决定，但播放期间的音频不得积压后补传，缓存必须保持有界。

Auto 播放期间不上传普通讲话，但保留本地唤醒词检测。检测到指定唤醒词后，取消当前云端回复、清空本地待播放音频，等待正在提交的音频及 DMA 尾部排空，再恢复 Listen 和上行。普通讲话不会触发打断；Manual 本轮不增加播放中唤醒词打断。2026-11-16 已在目标板实现并实测，识别受扬声器音量和声学条件影响，见 [Auto 唤醒词打断验收](auto-wake-word-interruption-2026-11-16.md)。

## 4. 模式切换与设备显示

通过双击 BOOT 按钮在 Manual / Auto 之间切换，网页不提供模式切换控件。双击应识别为一次模式切换，避免同时触发单击对应的收音或停止动作；与现有按键行为的协调在实现时确认。

设备屏幕在显示 Speak 或 Listen 时，同时显示当前交互模式，例如 `Speak · Auto`、`Listen · Auto`、`Speak · Manual`、`Listen · Manual`。运行状态和交互模式分别表达，切换后及时更新显示。

若在收音或播放期间切换模式，需妥善结束当前轮次并清理旧音频，再按新模式进入可用状态，避免沿用旧模式的上行和播放任务。重启后是否保留模式沿用现有配置机制，具体行为在实现时确认。

## 5. 统一配置网页

### 5.1 页面结构与视觉

将原小智配置页面与阿里云 Realtime 配置页面整合为统一的设备配置单页，保留原有配网功能，并将其提升为两种服务共用的网络设置。

页面从上到下依次为：

1. 顶部：设备名称、板型与网页到设备的连接状态。
2. 网络设置：当前 Wi-Fi、联网状态，以及扫描和更换网络入口。
3. 语音服务：小智服务 / 阿里云 Realtime 选择项及对应配置表单。
4. 声音设置：播放音量。
5. 高级设置与设备信息：默认折叠。

采用偏白背景、白色卡片、深灰文字和一种蓝色强调色，保持输入框与按钮样式统一，减少装饰图标、渐变和动画。电脑端内容宽度约 760 像素，手机端采用单列布局，控件保留足够的点击区域。

网页不提供 Manual / Auto 模式切换控件。服务选择与设备交互模式切换是两项独立操作；模式通过双击 BOOT 切换，并在设备屏幕的 Speak / Listen 状态处显示。

### 5.2 共用网络设置与配网流程

网络设置独立于小智或阿里云服务，支持查看当前 Wi-Fi 与连接状态、扫描热点、输入密码及更换网络。

首次进入配网时默认展开网络设置，引导用户先连接 Wi-Fi，再配置语音服务。已联网时收起为简短摘要，例如 `Wi-Fi：家庭网络 · 已连接`，点击“更换网络”后展开表单。

网络表单使用独立的“连接网络”按钮，语音服务表单使用“保存配置”按钮。修改服务配置时不重新提交 Wi-Fi 配置；连接网络时也不隐式保存尚未提交的服务配置。

保留原有设备热点配网入口，并进入同一套页面。切换 Wi-Fi 前明确提示连接过程可能导致页面断开；提交后显示“设备正在连接新网络，连接成功后请在同一网络下重新访问”。失败时沿用原有配网恢复机制，具体恢复行为在实现时核对现有代码。是否支持自动跳转或重新发现设备，待结合现有能力确认。

网页到设备的连接状态与设备到 Wi-Fi 的联网状态分别表达，避免在热点配网时把“网页可访问”误显示为“设备已联网”。

### 5.3 服务选择与配置表单

使用清晰的两个选项卡选择“小智服务”或“阿里云 Realtime”，仅展开所选服务的配置。两套服务参数分别保留，切回时无需重新填写。

切换选项卡用于编辑配置，点击“保存配置”后才正式应用并切换服务。当前实际使用的服务应明确标注，不能将尚未保存的选项显示为已经生效；按钮附近提示“保存后切换到该服务”。

小智区域保留现有接入必需配置；阿里云区域优先展示 API Key、模型及实际接口需要的地域或工作空间。有合理默认值的字段预填，自定义地址、调试代理及其他技术参数放入高级设置。准确字段以现有代码和后续接口核对结果为准。

字段名称放在输入框上方，仅在必要时补充一句用途说明。必填或格式错误显示在对应字段下方，避免用弹窗打断操作。

API Key 默认隐藏，支持显示和替换；已保存密钥以“已设置”表示，不将掩码当作真实值提交。不修改密钥时保留原值；明确替换后才提交新值。

### 5.4 页面状态与保存反馈

首次加载配置时显示“正在读取”，读取完成后允许编辑与保存；网页与设备断开后显示“设备已断开”，禁用依赖设备连接的提交按钮。

表单修改后允许保存，提交期间显示“正在保存…”，成功后显示“已保存”，失败时保留用户输入并给出具体原因。

保存成功与服务连接成功分别展示。如应用配置需要重连，保存后继续显示“正在连接小智服务”或“正在连接阿里云”，再展示最终连接结果，不以“已保存”代替服务连接成功。

### 5.5 声音、高级设置与设备信息

声音设置提供播放音量滑块与数值。高级设置收纳自定义连接参数、调试代理及诊断日志入口，默认折叠，避免技术字段占据首屏。

设备信息中展示固件版本、板型、网络信息及重启入口。网络摘要和设备信息只展示必要内容，常用配网操作保留在网络设置卡片中。

## 6. 实现与异常处理要求

- 上行开关应覆盖编码、发送队列和网络发送边界，防止关闭后仍发送积压的麦克风包。
- 恢复监听前清理旧音频，区分前后轮次，避免迟到的编码结果或网络事件重新带入旧数据。
- 取消回复时同步处理云端生成取消、本地播放停止和旧回复迟到音频，防止停止后继续播放。
- 无音频回复、服务端错误、断线和重连也应正确退出等待或播放状态，避免永久关闭上行。
- 应用状态变更遵循现有状态机，通过 `Application::SetDeviceState()` 执行；跨任务回调通过调度或事件通知主任务处理。

阿里云具体事件、VAD 配置及取消信令在实现阶段核对接口文档和现有代码后确定。本文约定设备交互行为，不预设尚未核实的协议字段。

## 7. 后续验收重点

- Manual：开始、结束、短句、连续多轮及播放期间主动开始新一轮。
- Auto：自动结束用户输入，播放期间无麦克风音频上行，本地播放完成后自动恢复监听。
- 播放结束恢复时不上传旧录音，不因回复尾音或余响误触发下一轮。
- 长回复播放完整，队列有界，播放结束后能够正常恢复收音。
- 停止回复后旧音频不再播放；无音频回复、错误、断线和重连不会卡住模式状态。
- 保留上行完整性、队列丢帧及降噪后人声完整性的检查。
- 双击 BOOT 只切换一次 Manual / Auto，不误触发单击动作；Speak / Listen 显示的模式与实际行为一致。
- 配置网页整合两种服务配置，移除模式切换控件，并检查手机端布局与保存反馈。
- 首次热点配网、Wi-Fi 扫描、成功连接、更换网络失败后的恢复，以及重新访问页面的引导均正常。
- 已联网时网络设置默认收起，修改服务配置不会提交或改变 Wi-Fi 设置。
- 服务选项卡切换不会提前改变实际服务，两套参数分别保留；保存与连接结果分别显示。
- 检查配置读取中、设备断开、保存失败及密钥保留/替换的页面行为。

上述行为需要后续代码实现和实体设备验证；原有 AEC 测试结果不能代替本方案的半双工验收。
